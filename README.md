# Singapore Weather Service

An HTTP service (Java 17 + Spring Boot 3) that reports current Singapore weather as a
unified JSON payload, sourcing data from **Weatherstack** (primary) with automatic
failover to **OpenWeatherMap**, plus a short-lived server cache that is served stale
when every provider is down.

## API

```bash
curl "http://localhost:8080/v1/weather?city=singapore"
```

```json
{
  "wind_speed": 20,
  "temperature_degrees": 29
}
```

- `wind_speed` — wind speed in km/h (rounded)
- `temperature_degrees` — temperature in °C (rounded)

`city` defaults to `singapore`. If every provider fails and no cached reading exists,
the service responds with `503 Service Unavailable` (RFC 7807 problem detail).

## Running

Set your API keys and start the app:

```bash
export WEATHERSTACK_ACCESS_KEY=your_weatherstack_key
export OPENWEATHERMAP_API_KEY=your_openweathermap_key

mvn spring-boot:run
```

Build and test:

```bash
mvn verify
```

A health endpoint for load balancers / orchestrators is available at

## How the requirements are met

### Unified response & hard-coded city
The public contract (`WeatherResponse`) is decoupled from provider payloads and from the
internal domain model (`Weather`), so vendor field names and units never leak to clients.
`city` defaults to `singapore`.

### Fast, transparent failover
Providers implement a single `WeatherProvider` interface and are ordered with `@Order`.
`WeatherService` walks the chain in priority order; the first success wins. Each provider
uses **short connect/read timeouts** (1s/2s) so a hung upstream can't delay the switch to
the backup. A provider can be disabled entirely via config (`weather.<provider>.enabled`)
without a code change.

### Caching + stale-on-failure
`WeatherCache` keeps the last reading **per city** and never evicts on expiry:

1. A **fresh** reading (within the 3s TTL) is served without touching any provider.
2. On a miss, providers are tried in order and the result is cached.
3. If **all** providers fail, the last (stale) reading is served rather than erroring.
4. Only with no reading at all do we return `503`.

### Scalability & reliability
- Stateless service — scale horizontally behind a load balancer.
- **Single-flight refresh**: a per-city lock ensures only one thread refreshes a given
  city at a time, shielding upstreams from a thundering herd under load.
- The 3s cache collapses bursts of traffic into at most one upstream call per city per
  window, keeping you well within provider rate limits.
- Actuator health probes for readiness/liveness in Kubernetes.

### Safe for new developers
- Clear layering: `web` → `service` → `provider` → `domain`.
- **Adding a provider is a one-file change**: implement `WeatherProvider`, annotate the
  bean with `@Order`, done — nothing else needs to know.
- All tunables (TTL, timeouts, keys, enable flags) live in one typed
  `WeatherProperties` bound from `application.yml`.
- Unit tests cover failover, caching, stale-serving, and the HTTP contract.

## Configuration

| Property | Default | Description |
| --- | --- | --- |
| `weather.cache.ttl` | `3s` | Freshness window before a refresh is attempted |
| `weather.weatherstack.enabled` | `true` | Toggle the primary provider |
| `weather.openweathermap.enabled` | `true` | Toggle the failover provider |
| `weather.<provider>.connect-timeout` | `1s` | Connection timeout |
| `weather.<provider>.read-timeout` | `2s` | Read timeout |
| `WEATHERSTACK_ACCESS_KEY` | — | Weatherstack API key (env var) |
| `OPENWEATHERMAP_API_KEY` | — | OpenWeatherMap API key (env var) |
